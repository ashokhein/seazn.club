# v17 Phase 1 — Re-org MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the v17 packaging re-org that needs **no new runtime subsystem** — the new plan-entitlement matrix, officials ungate, scorers retirement, dead-key disposition, Pro↔Pro Plus "coming soon" labels, and the updated pricing page.

**Architecture:** One Flyway migration upserts `plan_entitlements` to the SPEC-1 §3 target matrix. Enforcement is unchanged (the resolver already reads the matrix). Manual-officials gates are removed from usecases. Render + help + i18n follow the DB. AI wallet, add-ons, and the Event Pass M/L ladder are **out of scope** (Phases 2–3).

**Tech Stack:** Next.js (vendored), Postgres + Flyway (`db:apply`), Drizzle-less raw `sql`, Vitest, Playwright e2e, 4-locale JSON dicts.

## Global Constraints

- Migrations: unqualified DDL; Flyway runs `-defaultSchema=seazn_club`. Shape: `insert into plan_entitlements (plan_key, feature_key, bool_value, int_value) values (…) on conflict (plan_key, feature_key) do update set bool_value = excluded.bool_value, int_value = excluded.int_value;`
- **Pass-row-load-bearing rule (V311):** the resolver treats an `event_pass` row **equal to** community as a no-op → the key drops out of the pass-lifted set. Any community cap raised in this phase whose key is pass-lifted MUST raise `event_pass` strictly above it.
- `int_value NULL` = unlimited; missing int row = deny/0; `bool false`/missing = off.
- Every user-facing string change → **4 locales** (en/es/fr/nl) + `pnpm i18n:check`. Help pages updated. Regression test that fails without the change. Smoke extended.
- Reuse existing floodlit/public theme + `.input`/`.label`/`.card`; frontend-design skill + Playwright screenshot-verify (light+dark) on the pricing page.
- Any billing/Stripe touch → stripe skill first. (Phase 1 touches no Stripe.)
- AI: **do not touch** `scheduling.ai*` or `officials.auto`/`ai.officials.auto` (Phases 2/6). `officials.auto` stays Pro-Plus-only this phase — the existing matrix test assertion for it stays green.

**Target matrix = SPEC-1 §3/§4/§5.** Only upsert `(plan, key)` pairs whose target differs from the current DB value (diff first).
